## Frosted UI via @whop/react

Frosted UI is Whop's design system for apps inside Whop. Use it through `@whop/react` 0.3.x, which bundles a pinned `frosted-ui` (0.0.1-canary.77). Don't also add the standalone `frosted-ui` package: it's a separate, newer copy, so its components don't see `WhopApp`'s theme context and throw "`useThemeContext` must be used within a `Theme`". shadcn or plain Tailwind work too if the user prefers.

```tsx
// app/layout.tsx
import { WhopApp } from "@whop/react/components";
import "./globals.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <WhopApp>{children}</WhopApp>
      </body>
    </html>
  );
}
```

- **App ID required:** `WhopApp` creates the iframe SDK during render, so the build fails with `[createSdk]: appId is required` unless `NEXT_PUBLIC_WHOP_APP_ID` is set or you pass `<WhopApp sdkOptions={{ appId }}>`.
- **Imports:** `WhopApp` and every Frosted component or hook (`Button`, `Text`, `Heading`, `Card`, `Dialog`, `Theme`, `useThemeContext`, …) come from `@whop/react/components`. The package root only exports `WhopThemeScript`, `WhopIframeSdkProvider`, `WhopIframeSdkContext`, and `useIframeSdk`. Some docs show root imports for components, and those fail.
- **Broken subpaths:** `@whop/react/checkout` and `@whop/react/websockets` are declared in `exports` but missing from the 0.3.2 package.
- **Postinstall:** `@whop/react/styles.css` is generated by the package's own postinstall script (`scripts/postinstall.mjs`, which only copies local Frosted CSS). pnpm 10 skips it by default, as does `--ignore-scripts`, and the build then fails with "Package path ./styles.css is exported … but no valid target file was found". Tell the user and let them decide whether to allow scripts for that one package (pnpm `onlyBuiltDependencies`, then `pnpm rebuild @whop/react`); never enable dependency scripts globally. Delete `.next` afterwards because Turbopack caches the failed resolve.
- **Storybook:** browse components at https://storybook.whop.dev

## Tailwind v4 Setup

```css
/* app/globals.css */
@layer theme, base, frosted_ui, components, utilities;
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "tailwindcss/utilities.css" layer(utilities);
@import "@whop/react/styles.css" layer(frosted_ui);
@config "../tailwind.config.ts";
```

```ts
// tailwind.config.ts (project root)
import { frostedThemePlugin } from "@whop/react/tailwind";
export default { plugins: [frostedThemePlugin()] };
```

- **Colors:** with the plugin on, use the 12-step scales (`bg-gray-2`, `text-gray-12`, `border-gray-a5`, `bg-blue-9`). Default Tailwind colors like `bg-blue-200` generate no CSS.
- **Scale meaning (Radix Colors):** 1–2 app backgrounds, 3–5 component backgrounds (normal, hover, pressed), 6–8 borders and focus rings, 9–10 solid fills (9 is the brand color), 11–12 text (12 is high contrast). `aN` steps are the alpha versions. Whop's Frosted UI guide lists a different 1–3/4–6/7–9/10–12 split; Frosted's Storybook points to Radix, so follow Radix.

## Theme and Layout

- **Theme:** `WhopApp` follows the host's light/dark theme. It sets the initial theme from the `whop-frosted-theme` cookie (or system preference), and its iframe SDK applies the host's theme changes live. Leave `appearance` unset, and use scale tokens instead of hard-coded colors so both themes work.
- **Layout:** many members use the Whop mobile app, so design mobile first and use `100dvh` (not `100vh`) for full-height views.
- **Empty states:** every list needs one, and admins need a clear first-run setup step.

## Iframe SDK

Client-only. `WhopApp` includes `WhopIframeSdkProvider`, so `useIframeSdk()` from `@whop/react` works anywhere under it. Without `WhopApp`, create one with `createSdk({ appId })` from `@whop/iframe`. Always pass `appId` explicitly: the fallback reads `process.env.NEXT_PUBLIC_WHOP_APP_ID`, which only Next inlines. Elsewhere (Vite, etc.) it throws.

| Method | Use |
|---|---|
| `inAppPurchase({ planId, id? })` | Open Whop's payment modal. Resolves `{ status: "ok", data: { sessionId, receiptId } }` or `{ status: "error", error }` ([payments.md](payments.md)) |
| `openExternalUrl({ url, newTab? })` | Leave the iframe safely (links, OAuth) |
| `getTopLevelUrlData()` | `experienceId`, `viewType` (`app`/`admin`/`analytics`/`preview`), `companyRoute`, `experienceRoute`, `baseHref`, `fullHref` |
| `getColorTheme()` | Host theme: `{ appearance?, accentColor?, grayColor?, … }` |
| `performHaptic({ type, style })` | Haptic feedback in the mobile app. `type`: `selection`/`impact`/`notification`; `style`: `light`/`medium`/`heavy` |
| `onNavigationStackChange({ stack, currentIndex })` | Keep the host back button in sync |
| `closeApp(null)`, `openHelpChat(null)` | Host controls (the argument is required) |

- `onHrefChange` is called automatically: the SDK syncs `location.href` to the host, so you don't need to call it yourself.
- `onColorThemeChange` is an event from the host, not a method. `WhopApp` already applies it. In `@whop/iframe` 0.0.6 the SDK's built-in handler consumes it, so an `onMessage.onColorThemeChange` callback never runs. For custom UI, listen for the `frosted-ui:set-theme` CustomEvent on `document.documentElement` (`event.detail` is the theme).

Use `openExternalUrl` for any link that leaves the app, so it opens properly on web and in the mobile app.

## Elements Appearance

Elements render in isolated frames, so your CSS can't reach them. Style them through the `appearance` prop (`theme`, plus `variables` for `--*` CSS variables and `classes` for documented `whop-*` parts):

```tsx
import { WhopElements } from "@whop/elements-react";
import { loadWhop } from "@whop/elements";

<WhopElements elements={loadWhop()} appearance={{ theme: { appearance: "dark", accentColor: "blue" } }}>
```

Inside a Whop app, pass `{ appearance: hostTheme.appearance }` from `getColorTheme()` as the Elements `theme` so they match. The host's color fields are plain strings, so map them to Elements' allowed values before forwarding them.
